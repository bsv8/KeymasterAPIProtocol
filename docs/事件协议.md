# 事件协议（规范正文）

本文与 `openapi/openapi.yaml` 的 `/api/events`、`EventEnvelope`、
`SnapshotEvent` 同为真值；冲突时以本文件为准并同步修正 YAML。

## 传输

- `GET /api/events`，`Accept: text/event-stream`。
- 可选 `topics` 查询参数：逗号分隔主题子集；省略表示全部；
  未知主题返回 `400`（v1 文本体）。
- 心跳为 SSE 注释帧（`:` 开头），默认每 15 秒，不作为业务事件，
  客户端必须忽略。

## 事件类型（SSE `event:` 字段）

- `snapshot`：订阅建立后的当前快照及版本信息。`data` 为
  `SnapshotEvent`：`protocolVersion`、`instanceId`、`topics`、
  可选 `revisions` 与 `state`。
- `change`：后续变化。`data` 为 `EventEnvelope`：
  `protocolVersion`、`instanceId`、`seq`（单调递增）、`topic`、
  可选 `entityId`、`revision`、`data`。
- `resync`：客户端必须重新同步。收到后结束本连接，重建订阅
  并重取快照。`data` 可为空对象。
- 无 `event:` 字段的帧按 `change` 处理（兼容任务级流）。

## 衔接与恢复

- 每次新订阅先发 `snapshot`，再发 `change`，不遗漏中间变化。
- `instanceId` 变化表示后台实例变化（重启/切换）：旧连接的迟到
  事件必须丢弃，重建订阅并重取快照。
- 序号缺口、队列溢出或慢消费者跟不上时，服务端发送 `resync`；
  客户端不得静默丢弃关键状态。
- 取消订阅、页面卸载、窗口关闭后清理订阅资源。

## 初版范围

- 初版不承诺历史事件重放：每次重新连接重新取得快照，
  不引入 `Last-Event-ID` 持久事件日志。
- 快照为全量当前状态的起点；高频进度可在服务端合并为最新状态，
  但最终状态必须可达。
- 事件不含密码、私钥及其他秘密。业务推进仍经命令 API，
  不靠前端广播事件执行资金操作。

## 主题

`connection | wallet | balance | task | roots | settings | collector`。
各主题呈现的变化见工程仓产品需求；本协议只冻结包格式与恢复行为。
