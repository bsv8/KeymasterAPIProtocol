# 协议（规范正文）

真值：`spec/protocol.yaml`。DTO、方法、错误由 `tools/gen` 派生，生成文件禁手改。

## 传输

- 复用现有监听端口，默认 `127.0.0.1:8790`，WebSocket 入口统一 `/api/ws`。
- `--api` 为 `http/https` 基地址时转换为对应 `ws/wss` 地址；也支持显式 WS 地址；不新增端口配置。
- HTTP 仅承担静态 Web 与 WebSocket 升级；旧业务 HTTP API 与 SSE 已退役。
- 严格校验 Host/Origin；反向代理经显式外部钱包 URL 与可信代理配置，不盲信转发头。

## 握手

- `hello`: `{product, apiVersion, client:{name, version}}`
- `welcome`: `{product, apiVersion, instanceId, connectionId, limits}`
- 精确匹配 `product:"km"` 且 `apiVersion:"v1"`；不协商；失败直接返回版本错误，不回退其他后台。
- `instanceId` 每次后台启动重新生成；`connectionId` 每次连接重新生成。
- 后台可在 `welcome` 公布更低资源限制。

## 消息

| 消息 | 职责 |
|---|---|
| `hello/welcome` | 建立连接、校验身份、公布资源限制 |
| `request` | `{id, method, params, attachments?}`；`attachments` 为附件声明 `[{id, bytes}]` |
| `response` | `{id, result}` 或 `{id, error:{code, message, retryable}}` |
| `binary` | `{requestId, attachmentId, declaredBytes, data}`；一附件对应一完整应用消息；首版无分片续传 |
| `cancel` | 尝试取消指定在途调用 |
| `subscribe/unsubscribe` | 管理订阅；`unsubscribe` 优先按 `subscriptionId` 删除单条，仅 `topics` 时按主题集合匹配 |
| `snapshot/event` | 快照及后续变化 |
| `resync` | 要求重取快照 |

- 同一连接内不复用请求 ID；重复 ID 不得重复执行。
- `snapshot` 按订阅 ID 投递；`event` 只投递给包含该主题的订阅；取消一条订阅不得影响同连接的其他订阅。
- ID 只关联调用，不自动成为资金或文件操作的持久幂等键。
- 普通查询一次调用一次响应；下载提交返回持久任务 ID，后续查询或订阅任务；Connect 审批由 Connect 模块管理。
- `cancel` 返回已请求取消、已结束、当前阶段不可取消、找不到请求等明确结果；取消成功不等于副作用已回退。
- 断线后不自动重发写入、签名、付款或任务提交。
- 传输错误与业务错误分开；对外 Connect 错误只用其正式错误表。

## 二进制、限额和背压

- Storage、MSFile、加解密正文使用二进制消息，不强制 base64。
- 请求 ID、附件 ID、声明长度与数据关联；重复、缺失、超时、长度不符均拒绝。
- 发送顺序：请求先声明附件（`request.attachments`），再逐个发送 AttachBegin + 二进制帧；
  服务端在处理请求前同步预注册声明并校验调用者，未声明的附件帧直接丢弃，未收齐
  不执行业务。声明缺失的请求按无附件执行（保持兼容）。
- 未收齐和未校验完整前不执行业务；未绑定附件不无限暂存；结束、取消、断线释放附件资源。
- 默认值：JSON 控制消息 1 MiB；单个二进制附件正文 16 MiB；完整二进制帧另允许 64 KiB 协议头开销（4 字节头长 + JSON 头）；每连接未完成附件 32 MiB；每连接待发送 32 MiB；在途普通请求 16 个；附件期限 30 秒。
- 硬限制：Storage 明文 16 MiB；MSFile Seed 16 MiB；Block 256 KiB。加密信封按 cc 现有格式计算上限。
- 普通状态可合并；响应和最终结果不静默丢弃；无法可靠交付时关闭连接，恢复后查询或重取快照。

## 事件、心跳与重连

- 主题：`connection/wallet/balance/task/roots/settings/collector/connect`（`connect` 承载待办/在线/许可/历史变化，订阅先快照后事件）。
- 先快照后变化，二者衔接不漏事件；每个主题的序号连续；订阅过滤不制造假缺口（空主题集合表示全部）；实体变化携带适用 revision。
- 实例变化、序号缺口、队列溢出触发重新同步；消息总线不替代账本、outbox 或持久任务。
- App 结果、签名及解密内容只定向返回，不进入共享广播；事件不含密码、私钥及其他秘密。
- 心跳：服务端每 15 秒 Ping，45 秒未确认存活则断开。
- 只重连原地址，间隔 1、2、4、8、15 秒，之后停止自动尝试并提供显式重试；重连重取快照。
- 关闭码：`1000` 正常、`1002` 协议违规、`1008` 策略拒绝、`1009` 过大、`1011` 内部错误。普通业务拒绝经响应表达。

## 方法与错误

- 方法全表见 `spec/protocol.yaml#methods`；参数/结果类型见同文件 `schemas`。
- Connect 五类操作（`identity.get`/`intent.sign`/`cipher.encrypt`/`cipher.decrypt`/`payment.pay`）默认逐次确认，无自动许可建待办，有许可走同一业务路径；`connect.approvals.decide` 仅批准可附 `grantAuto`，`connect.auth.revoke` 按精确 `origin/appPublicKey/appId` 撤销，新增 `connect.permissions.list/revoke`（仅取消）、`connect.history.list`、`connect.apps.list`、`connect.connection.pause`（暂停保留授权，由 resume 恢复）；`channel.*`/`msfile.*` 未开放，不宣称完整 SDK 对齐。
- 错误码见 `spec/protocol.yaml#errors`；新增后台错误码在规范统一定义。
